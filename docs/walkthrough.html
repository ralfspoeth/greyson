Greyson, in five steps

Parse → Pointer → Selector → Shape → a real specification. Every result on this page is computed live from the document in the pane alongside — nothing here is a canned screenshot.

The document is a value

JsonValue — a sealed hierarchy of records

Parsing gives you back a tree of records, and the hierarchy is sealed: six concrete types, no more, ever. That is the whole point — the compiler can prove a switch over it is exhaustive, so there is no else branch to forget and no instanceof ladder to keep in step with a growing type set.

var doc = Greyson.readValue(reader).orElseThrow();

// exhaustive — add a case and the compiler tells you where
int depth = switch (doc) {
    case JsonObject(var members) -> 1 + members.values().stream()...
    case JsonArray(var elements) -> 1 + elements.stream()...
    case Basic<?> _ -> 0
};

One value: Pointer

Pointer = JsonValue → Optional<JsonValue>

A Pointer answers where is this one value? Build it segment by segment, or parse a slash-separated path. A miss is an empty Optional, not an exception — because in data from the wild, a miss is a normal outcome.

var p = Pointer.self().member("portfolio").member("owner");
var q = Pointer.parse("portfolio/owner");        // equivalent

String owner = q.stringValue(doc).orElse("unknown");
String must  = q.stringOrThrow(doc);  // names the pointer when it misses

RFC 6901 strings work too, via Pointer.fromJsonPointer("/portfolio/positions/0/isin") — so pointers emitted by JSON Patch or OpenAPI drop straight in. And a Pointer writes as well as reads: set and remove operate on a Builder, never on the immutable value.

Many values: Selector

Selector = JsonValue → Stream<JsonValue>

Where a Pointer answers which one, a Selector answers which ones. It returns a Stream, so it plugs into flatMap and the rest of the standard library — there is no bespoke pipeline to learn.

Stream.of(doc)
      .flatMap(Pointer.parse("portfolio/positions").select(Selector.all()))
      .flatMap(Selector.all().point(Pointer.self().member("ccy")))
      .forEach(System.out::println);

Pick a pipeline

The two types bridge in both directions, which is what keeps a query inside the algebra instead of spilling into ad-hoc loops:

pointer.select(selector)go to one place, then fan out
selector.point(pointer)fan out, then narrow each result
selector.where(shape)keep only the results of a given shape

A Selector filters by type — objects(), numbers(), strings(). The next act filters by shape.

What is wrong, and where: Shape

Shape = JsonValue → Stream<Violation>

A Shape describes a value's structure. Apply it and you get the defects — so an empty stream means the value is fine. That inversion is the whole design: a boolean can only say "no", and "no" is useless when you have a thousand records and need to know which three are broken and why.

var POSITION = member("isin", string())
        .and(member("ccy", matching("[A-Z]{3}")))
        .and(member("amount", number()));

Pointer.parse("portfolio/positions")
       .must(each(POSITION))
       .violations(doc)
       .forEach(System.out::println);

Violations, computed live

Repair the document and watch them go

Naming a member is requiring it. Either you care about a member — and then about its value — or you do not mention it. optional covers the third case, where absence is fine but a present value still has to fit.

member("ccy", string())ccy is there, and is a string
optional("ccy", string())if ccy is there, it is a string
exact(Basic.of("2.0"))equals "2.0" — for discriminators
exactlyOne(Map.of(...))exactly one of these members, satisfying its shape
each(number())an array whose every element is a number
a.or(b)either holds — for union-typed fields

A shape is a value: immutable, comparable, usable as a map key, and printable via explain(). The same shape that produced the report above also yields a predicate() for Stream::filter — and because the violation stream is lazy, the predicate stops at the first defect and never builds a message it will not use.

A real specification

JSON-RPC 2.0, §4 and §5

This is the case Greyson was built for. The JSON-RPC 2.0 rules are not merely "these members, those types". jsonrpc must equal the literal "2.0". id is optional but constrained — and absence carries meaning: no id makes the message a notification, and no response is owed. So conflating "absent" with "present but malformed" is not leniency; it turns a request into a notification and leaves the peer waiting for a reply that never comes.

static final Shape REQUEST = member("jsonrpc", exact(Basic.of("2.0")))
        .and(member("method", string()))
        .and(optional("id", string().or(number()).or(nul())))
        .and(optional("params", array().or(object())));

// result and error are mutually exclusive — never both, never neither
static final Shape RESPONSE = member("jsonrpc", exact(Basic.of("2.0")))
        .and(member("id", string().or(WHOLE).or(nul())))
        .and(exactlyOne(Map.of("result", anything(), "error", ERROR)));

Turned around, the same shape becomes a conformance oracle: rather than asserting a particular response for a particular request, assert that whatever the processor emits satisfies RESPONSE, down every path. That is the assertion that catches an invalid request producing no response at all — because "nothing" is not a response object.
